# SandClaimer 迭代 PRD

| 项 | 值 |
|---|---|
| 产品 | Sand 资格领取器（SandClaimer） |
| 仓库 | `dtb-cursor-tools` |
| 基线 | `TOOL_VERSION = 1.2.1`（`sand_patch.py`） |
| 日期 | 2026-09-06 |
| 状态 | 待审阅（产品级 PRD，不是单功能规格） |
| 读者 | 维护者 / 实现代理。大功能仍须另写 `docs/superpowers/specs/` 再拆计划 |

本文把「这个项目怎么迭代」收成可排期的产品文档：先写清现状和风险，再按两条产品线给出版本包、验收标准和明确不做的事。

---

## 0. 结论（先看这页）

SandClaimer 不是一个功能，是**两个产品塞在同一个窗口、共用一个版本号**：

1. **号池桌面**（QGIS 线）：导入 / 验证 / 领取 / 导出 / 切号 / 只读会话。打 `cursor.com` 与 `api2.cursor.sh`，跟 Cursor 小版本几乎无关。
2. **本机补丁**（ogr2ogr 线）：把 Cursor 安装从 vanilla 转成 Sand 本地回路。钉死 **3.18.9**；Cursor 一换构建，锚点就丢。

名头是「资格领取器」，付费号（Pro / Pro+ / Ultra）套餐**自带** Sand，领取对它们是短路。日常真正被用的是：验号、三池额度、分类导出、切号、打补丁。迭代时不要按名字去堆「领取」功能。

**下一版不要做踢会话。** 先做两件能保住产品的事：

| 优先级 | 版本包 | 做什么 | 为什么先做 |
|---|---|---|---|
| P0 | **1.2.2 质检与发版债** | 补 README 里写了却不存在的测试；Changelog；打包版本源拉齐；登录会话规格改成「已落地」 | 现在几乎无法安全改补丁或口径 |
| P0 | **1.3.0 补丁多版本** | 对齐 `cursor-account-manager-main` 已验证的 3.18.9 / 3.18.25 / 3.19.13 | 用户一自动更新，Bot 回路就死，面板还可能显示成功 |
| P1 | **1.4.0 号池体验** | 会话票刷新、并发限流、Mac 凭据、导出/验证小缺口 | 号池会随时间腐烂，不依赖 Cursor 换版 |
| P2 | **1.5.0 会话写操作** | 踢会话（须先实测 revoke 接口）；机器码只读关联 | 规格 §9 已标明第二期；误踢本机不可逆，单独规格、单独开关 |

过程不变：大功能 = 书面规格 → 实现计划 → 先写失败测试。号池改动走不联网 HTTP mock；补丁改动必须有 vanilla 往返。

## 1. 产品定位

### 1.1 是什么

本机桌面工具（Python + pywebview）。只跟 Cursor 官方通信，token 不上传第三方。

面向号池操作者，一次做完四件事：

- 把各格式 token 收进一张表，验证死活与套餐。
- 看 Bot / Auto / 高级 三池和 Sand 资格口径。
- 需要时给免费号 / 团队号走领取；付费号只确认。
- 给**本机正在用的那份** Cursor 打 / 卸 Sand 回路补丁，并用 Cursor 自己的日志验证到底走没走本地。

### 1.2 不是什么

- 不是 Cursor 官方产品，也不是 VS Code 插件商店应用。仓库里的 `cursor-account-manager-main` 是**参考实现**（上游插件，已跟到 3.19.13），不是本工具的运行时依赖。
- 不是 GIS / 制图软件。下文「外业 / 编稿 / ogr2ogr」只是迭代分工用语。
- 不做 Cloud Agents `crsr_` API、不发明 sessions 里没有的电脑名 / IP、不在领取路径上拉会话。

### 1.3 用户与场景

| 角色 | 场景 | 成功长什么样 |
|---|---|---|
| 号池操作 | 粘贴 / 导入 JSON → 自动验证 → 按套餐和 Bot 是否用过导出 txt | 死号不会被当成活号；导出行可原样再导入 |
| 本机使用者 | 探测本机号、切号（网站票先换成客户端票）、可选重置机器码 | 切完能发消息，不必立刻重登 |
| 打补丁 | 检测规则 → 打补丁 → 看逐步报告 → 「验证生效」读日志 | 11 条规则状态可信；走 `managed-local` 而不是 `connect`+401 |
| 免费号 | 「网页领取」用隔离浏览器打开 onboarding | 能绑卡；工具不替用户提交信用卡 |

### 1.4 价值真实分布（决定排期）

| 能力 | 1.2.1 状态 | 对用户的实际权重 |
|---|---|---|
| 验证 + 三池 + 失效判定 | 已交付，口径经过实测 | 最高。每天都用 |
| 分类导出 txt | 已交付 | 高。号池交接 |
| 本机补丁 + 报告 + 日志验证 | 已交付，但只认 3.18.9 | 极高，且最脆。Cursor 一更新就归零 |
| 切号 + web→session 交换 | 已交付 | 高。网站票直写客户端会「能显示、一发就掉」 |
| 批量领取 | 已交付 | 中。付费号短路；团队号 / 免费号才有动作 |
| 只读登录会话 | 代码已落地，规格仍写「待审阅」 | 中。辅助看有没有多端挂着 |
| 踢会话 / 跨号机器码关联 | 明确未做 | 未验证需求。高风险，不进 1.3 |

## 2. 现状盘点（相对 1.2.1）

### 2.1 已交付（按制图工序）

```text
外业调绘    真机接口与 Agent Host 日志
内业编稿    docs/superpowers/specs + plans（目前只有 login-sessions）
配准口径    sand_api.py / accounts.py（token、三池、alive、sessions 归一化）
符号化出图  app.py + web/（列表、pill、弹层、导出、补丁面板）
地理处理    sand_patch.py（vanilla → sand 回路）
质检        patch_report.py + 仅 test_login_sessions.py
印前出版    TOOL_VERSION → build.bat / build-mac-app.command / installer.iss
换版重测    未做（仍单驱动 3.18.9）
```

号池侧已有：token 混排识别、导入即验证、DPAPI（仅 Windows）、验证与领取短路、三池分开展示、on-demand 标注、分类导出、切号闸（过期 / 探活死 / web 票交换）、DoH 绕 DNS 劫持、会话 pill + 本机标记。

补丁侧已有：marker 规则、运行时扫 agent-host `dist`（不写死 657/675）、失败回滚、多安装提示、1.2.1 的 `SAND_LOCAL_ACTIONS_V1` / `SAND_SUBAGENT_LOCAL_V1`、读日志区分 `managed-local` vs `connect`。

### 2.2 已知缺口（深入）

**A. 文档与代码漂移**

- README 项目结构写了 `test_accounts_usage.py`、`test_sand_patch.py`、`test_patch_report.py`，仓库里**只有** `test_login_sessions.py`。
- 登录会话规格状态仍是「待用户审阅」，实现、单测、UI、README 接口表都已在。过程上等于「没验收就当发布了」。
- 没有 `CHANGELOG.md`，Git 只有两次提交，没有 Release。群里无法对上「你用的是哪一版补丁」。

**B. 补丁生存风险（最大）**

- `REQUIRED_CURSOR_VERSION = "3.18.9"`，下载 SHA 写死。
- 参考树 `cursor-account-manager-main` 已用 Changelog 跟到 3.18.25 / **3.19.13**。上游明确写过：3.19.13 重写本地 Agent 内核，旧锚点「界面可显示已注入，实际仍走官方 RunInference」。本仓库会重复这个坑。
- 补丁没有 vanilla 往返测试。改 `sand_patch.py` 只能靠本机一份 3.18.9 肉眼看。

**C. 一个版本号绑死两条线**

号池修导出文案也要 bump `TOOL_VERSION`，和「补丁必须重打」无法区分。用户无法从版本号判断要不要重打补丁。1.2.1 是靠面板「补丁需升级」和 marker 补的；发版说明里没有稳定约定。

**D. 凭据会腐烂**

- JWT `exp` 约 60 天。验证会标失效，但号池**不会**用已保存的 refresh 去续期。
- 切号路径会把 web 票换成 session 票，换到的 refresh **写进 Cursor，不写回号池**。下次再切同一行，仍拿旧 web 票去换。
- Mac / Linux：`accounts.py` 的 DPAPI 直接 `return None`，落盘明文。

**E. 打包版本源不统一**

README 说版本只来自 `TOOL_VERSION`。`codemagic.yaml` 仍写死 `--product-version=1.0.0`。`installer.iss` 有默认 `1.2.1`（`build.bat` 传入时没问题，单独跑 ISCC 会和源码再次分叉）。

**F. 并发与官方限流没有产品约定**

验证默认并发 3、上限 10。每个活号一次验证约 6 路 HTTP。号池一大，429 / 偶发 204 会把「无法判定」和「失效」搅在一起。现有逻辑已经用 api2 二次确认避免误杀，但没有退避、没有「本轮跳过」。

**G. 会话二期不能直接开工**

规格 §9：踢会话、机器码跨号关联、hostname/IP 占位。当前接口**不返回**设备信息；JWT **没有** `sid`，无法把「当前这张票」对上列表某一行。没有实测 revoke 之前做踢会话，误踢本机等于把正在用的号踢下线。

### 2.3 模块职责（改哪里）

| 层 | 文件 | 允许改的需求类型 |
|---|---|---|
| 配准 | `sand_api.py`、`accounts.py`、`resolve.py` | 新官方接口、口径、token 格式、alive 规则 |
| 本机登录 | `local_cursor.py`、`browser_login.py` | 读写 `state.vscdb`、机器码三处、隔离浏览器 |
| 出图 | `app.py`、`web/*` | pill、弹层、批量、补丁面板展示 |
| 转换 | `sand_patch.py`、`sand_rpc.js`、`patch_report.py` | Cursor 换版、新 marker、规则判定 |
| 出版 | `build.bat`、`installer.iss`、`codemagic.yaml`、`build-mac-app.command` | 版本源、产物名 |

禁止：在 `web/app.js` 里重算三池或 alive；在 `sand_patch.py` 里改领取口径；写死 agent-host chunk 文件名。

## 3. 迭代原则

1. **先外业后编稿。** 新字段、新接口、新锚点必须真机或真日志，禁止按文档猜。规格里不许出现「待定」。
2. **两条线分开排期。** Cursor 升版本走补丁线，不要顺手改导出；号池加 pill 不要动补丁规则。
3. **alive 口径锁定。** 只由数据接口状态码（及现有 JWT exp / `auth/me` + api2 二次确认）决定。sessions、领取、导出注释都不得改写 alive。
4. **补丁可逆。** 新规则必须带 marker；卸载按 marker 揭掉；原代码保留为死代码或可还原片段。写入失败整次回滚。
5. **版本号语义。**
   - 补丁规则有新 marker、用户必须重打 → **次版本或修订 + 发版说明第一句写「请重打补丁」**。
   - 只改号池 / UI / 打包 → 修订号，说明写「无需重打补丁」。
   - `TOOL_VERSION` 仍是唯一来源；所有打包脚本必须读它（含 Codemagic）。
6. **测试分层。** 号池：不联网 unittest + mock `_get/_post`。补丁：vanilla 安装树往返（打上再卸，字节回到原样）。不强制 UI 截图，但改出图层必须人工点一遍列表 / 验证 / 领取 / 补丁面板（共享账号状态）。
7. **参考树只吸收锚点，不合并产品。** 从 `cursor-account-manager-main` 移植的是版本表和 minify 锚点，不是它的踢设备 / 插件 UI。

输入是 token，输出是列表状态和 txt。失败按行隔离。状态在 `accounts.json` + `status.json`。

近期只做「图层字段和布局」，不做「编辑要素几何」（踢会话 = 写操作）。

### 5.2 1.3.0 — 补丁多版本（P0，ogr2ogr 线）

**目标：** 在参考树已验证的三个 Cursor 版本上，注入成功且卸载能还原；3.19.13 不得再出现「pill 显示已生效、实际走云端 RunInference」。

**决策（本 PRD 建议，实现前可在补丁规格里微调）**

| 点 | 建议 |
|---|---|
| 支持注入的版本 | `3.18.9`、`3.18.25`、`3.19.13`（与参考树 `TESTED_CURSOR_VERSIONS` 对齐） |
| 其它版本 | 继续拒绝写入，文案列出已测试版本 + 下载链接；不再只给 3.18.9 一条 SHA |
| 卸载 | 必须能拆本工具历史 marker，以及参考树 2.x 时代标记（若本机被插件打过）。禁止卸载时把无关用户改动当补丁清掉 |
| 3.19 直连流 | 元数据必须是官方 `resolvedModelMetadata.promptModelInfo` / `useDsv3Harness` 形态，禁止整包写入模型函数（参考树 2.3.20 踩过的坑） |
| 规则清单 | `patch_report.RULES` 按版本显示：本构建没有的锚点标「可选·无锚点」或「本版本不适用」，不得把 3.19 独有规则在 3.18.9 上判成失败 |

**范围**

| ID | 需求 | 验收 |
|---|---|---|
| P-130-1 | `sand_patch.py` 双轨（或按 `product.json` version 选规则集） | 三个测试版本各有一份夹具或本机安装；`install` 后 stream 生命周期计数达到该版本期望；失败不落盘 |
| P-130-2 | `app.py` 的 `REQUIRED_CURSOR_VERSION` / `CURSOR_DOWNLOADS` 改为「已测试版本表」 | 版本不符时给出对应平台安装包，而不是永远指向 3.18.9 |
| P-130-3 | `patch_report` 结论改为「N/M 条**本版本必需**规则生效」 | 3.18.9 机器不会因为缺少 3.19 锚点被判失败 |
| P-130-4 | 卸载往返 | 打上再卸，夹具字节回到原样；旧 marker 也能揭 |
| P-130-5 | 发版说明强制第一句 | 「请重打补丁；支持 Cursor …」 |
| P-130-6 | bump `TOOL_VERSION` 到 1.3.0 | 所有打包脚本读到 1.3.0 |

**非目标：** 移植参考树的踢设备、路由文案汉化、Grok 4.5/4.6 prompt 互斥（除非 1.3 真机证明本回路也中招——那时单开补丁热修 1.3.1）。不改号池导出格式。

**依赖：** 1.2.2 的补丁测试骨架，否则 1.3 无法回归。

**实现前必做外业：** 在 3.19.13 真机打一次「验证生效」，确认 `managed-local` 与 401 是否仍是同一套日志关键字。关键字变了要先改 `runtime_report`，再改写入规则。

### 5.3 1.4.0 — 号池体验（P1，QGIS 线）

**目标：** 号池在 60 天票周期内少腐烂、批量验证少误杀、Mac 不把 token 明文放到用户目录还毫无提示。

| ID | 需求 | 验收 |
|---|---|---|
| A-140-1 | **刷新策略（只读号池）**：若账号存有 refresh，或切号交换曾得到 refresh，验证发现 JWT 将过期 / 已过期时尝试刷新，成功则回写 token，失败再标失效 | 单测 mock poll/refresh；活号不因「只过了 exp、refresh 仍有效」被杀掉。刷新失败不得清掉旧状态里的套餐展示（可标失效） |
| A-140-2 | 切号换到的 session/refresh **写回号池该行** | 再切同一号不再拿过期 web 票 |
| A-140-3 | 批量验证遇到连续 429 / 网络 0：降低并发并在进度条说明，本轮 `alive=None`，不改成失效 | 单测或可重复的 fake；UI 有一句人话 |
| A-140-4 | Mac：Keychain 或等价加密；读不到密钥时明确提示「将明文保存」而不是静默 | Windows 仍 DPAPI；Linux 至少提示明文 |
| A-140-5 | 列表筛选：只看失效 / 需绑卡 / 未开通 / 本机 | 不改导出格式 |

**非目标：** 踢会话、展示 IP、改三池公式、改导出行 `邮箱----user_id::token`。

**规格：** 刷新端点必须再做一次外业（现有 `exchange_web_to_session` 只覆盖 web→session，不等于任意 refresh）。未实测成功之前，A-140-1 不得开工。

### 5.4 1.5.0 — 会话写操作（P2，单独规格，默认不做）

**只有同时满足才开规格，否则本版本整包取消：**

1. 真机确认官方 revoke / logout 接口（路径、鉴权、是否能指定 `sessionId`、失败码）。
2. 能可靠识别「本机当前这条客户端会话」——今日 JWT **没有** `sid`，本机 pill 只是账号级。做不到就**禁止**提供「踢除本机以外全部」，避免误踢自己。
3. 默认关闭；每次踢要二次确认；踢本机必须额外警告并在文案写清「会把正在用的 Cursor 踢下线」。

| ID | 需求 | 验收 |
|---|---|---|
| S-150-1 | 弹层增加「踢掉这条」（非本机） | 只调用已实测接口；失败不改 alive；本机当前会话按钮禁用或极强确认 |
| S-150-2 | 机器码关联（原需求 C）若做：只读对比本机 `telemetry.machineId` 与号池已有字段 | **不展示、不编造**接口没有的 IP/OS；不做跨号写入 |
| S-150-3 | sessions 若日后增加 hostname / IP | 有字段才展示，规格另改，不提前占位 |

**非目标：** `crsr_` Admin API、重置别人的机器码、批量踢全号池。

## 6. 每个版本的工序（制图工作流）

对 1.3 / 1.4 / 1.5 每一个大包，实现代理按这一张表走，不要从编码起手：

| 工序 | 产出 | 停手条件 |
|---|---|---|
| 外业 | 接口原始响应或 Cursor 日志摘录，贴进规格附录 | 没有 200/401/回落原因的实录 |
| 编稿 | `docs/superpowers/specs/日期-代号-design.md` | 有 TODO、有「大概」 |
| 计划 | `docs/superpowers/plans/日期-代号.md`，任务含失败测试 | 任务一次改两条产品线 |
| 配准 / 转换 | 代码 + 单测变绿 | 号池测试联网；补丁无往返 |
| 出图 | UI；人工点共享状态的四个面 | 只截一张静态图 |
| 质检 | unittest +（补丁）规则报告 | README 再写不存在的测试文件 |
| 出版 | bump `TOOL_VERSION`、Changelog、打包脚本 | Codemagic 仍写死 1.0.0 |
| 换版说明 | Changelog 写清是否重打补丁 | 用户无法判断 |

1.2.2 可以不写新规格（行为不变），但必须修测试与文档。

## 8. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| Cursor 再次重写 agent-host | 1.3 的锚点作废 | 规则按版本分轨；锚点缺失拒绝写入；参考树 Changelog 当预警源 |
| 夹具版权 | 不能把官方 dist 整包提交 | 最小片段 / 本地生成 / gitignore |
| refresh 接口与 web 交换不同 | 1.4 做错会把活号写成坏票 | 先外业；写回前校验新票 `auth/me`；失败保留旧票 |
| 踢会话误踢本机 | 正在用的号掉线 | 1.5 默认不做；无 sid 则不做「踢其它」 |
| 双线同一 PR | 回滚时把无关功能一起撤 | 补丁 PR 不改 `web/`；号池 PR 不改 `sand_patch.py`（桥接文案除外） |
| 参考树行为与本工具不一致 | 抄错 3.19 metadata | 只移植已验证锚点；用本工具的 marker 与回滚策略 |

## 9. 待产品确认（不阻塞 1.2.2 / 1.3.0 开工）

下面三项 **1.4 / 1.5 规格开写前** 需要人点头。不定则保持「不做」。

1. 号池是否允许自动刷新 token 并覆盖落盘？（A-140-1）安全含义：本机文件里的票会变新。
2. 是否要做踢会话？若要，能否接受「在没有 sid 之前只展示、不提供踢」？
3. 机器码跨号关联是否仍要做？本 PRD 建议降级为「只读、本机、不展示接口没有的字段」，或整项取消。
